Updated 2026-09-25 (i18n pass). Supersedes the 2026-09-23 version of this file, which described `clean/`, `survey/`, and `models/` as missing and estimated MVP completion at 20-25%. ## Summary

67+ commits, all still on a single compressed development arc. The full data pipeline now runs end to end on real data: SAS microdata harmonization, yield/QC cleaning, survey-weighted district estimates (validated against a real published NISR report), satellite feature extraction including climatology and lead-time cutoffs, attainable yield and yield gap, a driver model (LightGBM + SHAP) per crop, and a nowcast model with a leave-one-year-out backtest that now also serves real per-district predictions, not just aggregate metrics. A round of external review earlier this session found and fixed four real correctness bugs in the nowcast (a satellite date-alignment error, feature leakage, and survey-noise contamination of the training target) and reported the results honestly, including where the models do not beat a naive baseline. 187 Python tests and 13 vitest tests pass, `ruff`/`mypy`/`eslint`/`tsc` all clean. **The API now has all 11 planned endpoints, none blocked**: `/nowcast` and `/nowcast/{code}/curve`, the last two, were built by making the nowcast's leave-one-year-out CV return its real out-of-fold predictions (previously only aggregated into metrics) and exporting them plus a new NDVI/rainfall curve table to `data/public/`. `models/scenario.py` and `export/` (simplified GeoJSON + 30 PDF briefs) both exist and are wired to their endpoints. **The web app now has a second real page**, `DistrictPage.tsx` (`/districts/:code`), a card-grid detail view that finally gives every one of those previously server-only-verified endpoints (`/districts/{code}/profile`, `/scenario/{code}`, `/nowcast`, `/briefs/{code}.pdf`) a real UI, linked from the map's district panel. `make lint && make test` is green across the whole repo. Both pages are now wired for i18n (en/fr/rw) via `i18next`/`react-i18next`, previously-installed-but-unused dependencies; language choice persists in the URL `?lang=` and in `localStorage`. **Kinyarwanda strings are an AI-authored first draft, not yet reviewed by a native speaker** (flagged in `docs/decisions.md` 2026-09-25 for the team's Kinyarwanda-focused reviewer). Rough MVP completion: **~88%** — the entire data-to-model pipeline is real, tested, and honestly validated, the API surface is fully complete, and the two web pages now cover the full data surface end to end in three languages; what's left is deployment, Kinyarwanda review, and process items outside the assistant's own execution (questionnaire PDFs from NISR, the user's platform choice for deployment).

## What is built and working

- **`src/agritwin/harmonize/`**: joins all 7 SAS years (2019-2025, Seasons A/B) into `stg_sas_plot_crop`, plus confidence and value-label sidecars.
- **`src/agritwin/clean/`**: adds `yield_kg_ha` and a priority-ordered `qc_flag` (missing data, zero/too-small area, not pure-stand, not SSF, above plausibility cap, outlier, ok).
- **`src/agritwin/survey/`**: Taylor-linearized (`samplics`), design-based weighted estimates at district/province/national x crop x season x year, with a three-tier reliability flag (`ok`/`use_with_caution`/`suppressed`). **Validated against the real NISR SAS 2025B report**: national maize yield 1,400 kg/ha (ours) vs 1,300 kg/ha (official), 7.7% off, inside our own 95% CI (`docs/validation.md`).
- **`src/agritwin/gee/`**: MODIS NDVI, CHIRPS rainfall, ESA WorldCover cropland, iSDAsoil, Rwanda district boundaries, a real NISR district_code <-> HDX/GAUL crosswalk, long-run climatology (MODIS 2001-2018, CHIRPS 1991-2020), and lead-time (partial-season) extraction for the nowcast. A real Season A date-alignment bug (satellite data was reading a full season ahead of the actual survey period, confirmed against NISR's own SAS 2025 Season A report) was found and fixed this session; see `docs/decisions.md` 2026-09-24.
- **`src/agritwin/models/attainable.py`**: k-means zoning (no AEZ layer is configured anywhere in this repo, the build guide's own documented fallback) and weighted-90th-percentile attainable yield, plus yield gap.
- **`src/agritwin/models/drivers.py`**: one LightGBM + SHAP model per MVP crop, GroupKFold by district, against a fold-safe naive baseline. 3 of 4 crops beat baseline (irish_potato +20.0%, beans +5.4%, maize +5.0%); **sorghum does not (-4.4%)**, reported plainly rather than tuned away.
- **`src/agritwin/models/nowcast.py`**: NDVI/rainfall anomaly + realistic prior-season-yield feature (which season is used depends on lead time and whether NISR would actually have published it by then, per `docs/nowcast-feature-timing.md`), leave-one-year-out CV, MAPE and MAE reported for two naive baselines plus ridge and LightGBM. **Honest verdict**: no crop beats the naive district-mean baseline by a margin large relative to the year-to-year spread; sorghum (LightGBM) and beans (ridge) show a real but modest, noisy directional edge, maize and irish potato do not (`docs/decisions.md` 2026-09-24). As of this session, the same leave-one-year-out CV also returns its real per-row out-of-fold predictions (previously discarded after being aggregated into metrics), written to `data/public/nowcast.csv` using whichever model actually won each crop x lead time's backtest, plus `data/public/nowcast_curve.csv` (NDVI/rainfall vs climatology per district x season x year x lead_months).
- **`src/agritwin/models/scenario.py`**: precomputed lever grid for the scenario explorer. Per district x crop, predicts mean yield under all 16 combinations of the 4 binary levers in `drivers.levers` (improved seed, inorganic fertilizer, organic fertilizer, irrigation), with a bootstrap 95 percent interval, using the already-fitted driver model. Wired into `run_drivers()`, writes `data/public/scenario.csv` (1,904 rows: ~30 districts x 16 configs x 4 crops). Labelled model-based not causal. Not yet exposed via an API endpoint (`GET /scenario/{code}` is unimplemented, same as before).
- **`data/public/`**: `district_yield.csv`, `yield_gap.csv`, `district_zones.csv`, `drivers.csv`, `drivers_by_district.csv`, `nowcast_backtest.csv`, `scenario.csv`, `geo/districts_adm2.geojson` (an HDX-sourced pipeline input, not an export output), `geo/rwanda_districts_simplified.geojson`, `briefs/{district_code}.pdf` (30 one-page district briefs), plus, new this session, `nowcast.csv` (1,821 rows: per-district-crop-season-year-lead early estimates) and `nowcast_curve.csv` (1,260 rows: per-district-season-year-lead NDVI/rainfall vs climatology). All pass `scripts/check_public.py`.
- **`src/agritwin/export/`**: `geo.py` (boundary simplification + district_code join) and `briefs.py` (one-page PDF per district: each MVP crop's latest yield gap and top-3 SHAP drivers, via jinja2 + weasyprint). Wired into `make export`. Deliberately does not take over `survey/`'s and `models/`'s existing direct-to-`data/public/` writes; only adds what didn't exist yet.
- **API** (`api/app/`): `GET /health`, `GET /api/v1/meta`, `GET /api/v1/kpis`, `GET /api/v1/districts` (now also carries the NISR `district_code` alongside `gaul_district_code`, joined server-side from `data/reference/district_crosswalk.csv`, see `docs/decisions.md` 2026-09-24), `GET /api/v1/districts/{code}/profile`, `GET /api/v1/yield-gap`, `GET /api/v1/drivers`, `GET /api/v1/backtest`, `GET /api/v1/scenario/{code}`, `GET /api/v1/briefs/{code}.pdf`, and, new this session, `GET /api/v1/nowcast` and `GET /api/v1/nowcast/{code}/curve` (crop/season/year filtered where applicable, every row including `"suppressed"` ones returned with a reliability flag rather than silently dropped, per `CLAUDE.md` golden rule 6). **All 11 planned endpoints now implemented, none blocked.** Live-verified with a real `uvicorn` run against real `data/public/`, not just unit tests. A real `DATA_DIR` semantics bug (the real `.env` config pointed at the wrong subfolder) was found and fixed earlier via this live check; a real NaN-to-JSON encoding bug (a not-yet-surveyed year's null `actual_yield_kg_ha`) was found and fixed while building `/nowcast` this session.
- **Compliance**: no raw microdata, secrets, or credentials anywhere in git history (checked across all commits, not just recent ones). `docs/ai-usage-log.md` now has real entries for every session, not just a header row. `NOTICE` (IP transfer + third-party licenses) exists. `CONTRIBUTING.md` exists.
- **Docs**: `docs/decisions.md` (23 dated entries), `docs/survey-design.md`, `docs/data-sources.md`, `docs/validation.md`, `docs/nowcast-feature-timing.md`, `docs/data/variable_audit.md`, `AI_DISCLOSURE.md`, `ORIGINALITY.md`.
